# 基础与按需扩展架构

PuKnowledge 采用 **通用基础（base）+ 按需扩展（extensions）+ 领域数据包（domain packs）**。配置中的 `core` 是基础层的稳定标识，为兼容既有安装不改名；它始终加载且不能被扩展替代。

公开仓只分发 `core`、`fs`、`longform`。下表中的私有领域扩展与兼容扩展用于说明边界和迁移策略，不属于公开默认安装。

## 分层

| 层 | 当前标识 | 责任 | 默认状态 |
|---|---|---|---|
| 基础 | `core` | 项目、任务、来源、证据、数据集、记录、关系、导入与能力目录 | 始终加载 |
| 通用扩展 | `fs` | 白名单目录内的只读文件访问 | 按需 |
| 创作扩展 | `longform` | 长文任务恢复、草稿、参考书和交接快照 | 按需 |
| 领域扩展 | `game`、`voice` | 需要专门行为与安全约束的游戏协作、声音试验 | 私有安装按需 |
| 兼容扩展 | `writing_legacy` | 旧小说集合索引、研究卡及检查点读取 | 仅迁移，不进入日常预设 |

`workspace_guide` 返回 `architecture.model=base_plus_extensions`，并列出本连接实际加载的基础与扩展。`owner` 预设不再自动加载兼容扩展；只有 `full` 或显式 `--modules ...writing_legacy` 才加载它。

## 小说能力放在哪里

小说不是底层项目类型。通用基础只保存项目、任务、来源、证据和结构化知识；小说、电影、文章等长文本共同使用 `longform`：

- `writing_*` 保存方向与交接快照；
- `draft_*` 管理候选稿和版本；
- `library_*` 管理用户有权使用的参考文本；
- 是否为小说、剧本或文章由项目元数据和领域结构定义，不产生新的底层存储体系。

因此新增影视改编、动画分镜或文章编辑时，优先增加有版本的 schema、模板和校验规则。只有出现新的执行行为或权限边界时，才新增 MCP 扩展。

## D&D 等领域信息放在哪里

D&D、具体规则版本、职业、法术、BAB 等都属于**领域数据**，不应成为基础工具参数或默认项目。目标形态是：

1. 以 `Dataset / Schema / Record / Relation / Evidence` 保存规则资料及项目采用关系；
2. 领域包只提供有版本的结构定义、受限枚举、声明式约束和合成样例；
3. 公式先作为带来源的声明保存，未接入受限计算器前明确标记为未执行；
4. 参考规则 `reference`、项目采用定义 `model`、具体实例 `state` 分开；用途不等于确认状态；
5. 需要规则计算时另加专用扩展，复用基础层的数据和证据 API，不开放任意 Python、SQL 或表达式执行。

当前 `novel_research*` 中的版本识别和旧研究卡仍由 `writing_legacy` 承担，只用于读取已有数据。它们不会出现在公开默认入口，也不得继续承载新的领域功能。新 D&D 数据进入结构化知识 API；完成数据迁移和指纹核对后，再删除兼容实现。

## 新需求的判断顺序

1. **只增加数据结构或业务词汇？** 新增领域 schema/数据包。
2. **需要已有工具的新组合？** 新增指南或模板，不新增工具。
3. **需要新的受限行为、外部服务或权限？** 新增扩展并声明依赖、读写性质和失败边界。
4. **只为读取历史数据？** 放入兼容扩展，给出迁移与退出条件。

扩展必须依赖基础层的项目身份、版本、证据和预览提交语义。扩展不得自行创建第二套来源、任务、会话或 Canon 系统。

## 退出旧兼容层的条件

- 已有研究卡、检查点、来源元数据和集合索引可由中性接口按固定指纹读回；
- D&D 版本信息已迁为领域数据，且通用代码中不再维护相关枚举；
- 真实数据库完成只读对照，历史 revision 与 fingerprint 保持可追溯；
- ChatGPT、Codex/Work 及其他受支持宿主不再依赖旧工具名；
- 删除兼容模块前保留迁移说明和明确的最后支持版本。

兼容层退出不要求删除历史数据库，也不把候选研究内容提升为已确认事实。
