# PuKnowledge 商业能力边界

本文区分“产品可以调用某项外部能力”“产品具备授权限制”和“产品已经可以真实
收费”。三者不是同一状态。

## 当前状态

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| PuKnowledge 开源 MCP | `FREE_OPEN_SOURCE` | Apache-2.0，本地单用户运行；没有购买或订阅要求 |
| Agensi Skill | `LISTING_CANDIDATE` | 可准备工作流 Skill；尚未提交、批准、定价或收款 |
| PuCatch/Magpie 适配 | 可选外部依赖 | 当前只读取显式配置的本地服务能力；不负责收费 |
| PuKnowledge 订阅/SaaS | 未实现 | 没有账户、多租户、配额、权益、计量、账单或退款系统 |
| PuKnowledge 自有支付 | 未实现 | 没有支付渠道、商品、真实订单或结算 |

因此，PuKnowledge 目前不是付费 SaaS，也没有按调用收费。它可以被一个付费
Marketplace Skill 指导使用，也可以在未来连接由其他产品单独授权的能力，但这
不会自动让 PuKnowledge 本身成为收费服务。

## Magpie/PuCatch 与 PuKnowledge 的关系

PuKnowledge 的 PuCatch 适配器是可选的本地 HTTP 客户端。它负责查询能力并在
用户授权后创建受控采集任务；它不读取 Magpie 的购买状态，也不处理订单、订阅、
用量余额或退款。

Magpie/PuCatch 可以在自己的产品中实现试用、购买或许可证校验。即使该产品的
商业链路已经准备或上线，PuKnowledge 也只是调用一个“已经可用的外部工具”。
除非双方增加明确的服务鉴权和权益契约，否则不能把这种调用描述为 PuKnowledge
的付费调用。

一个正式的付费外部能力至少需要返回并执行：

- 稳定的产品/服务标识和版本。
- 当前权益状态及其可信来源。
- 可调用能力、配额或限制。
- 权益缺失时的明确错误，不静默降级为收费结果。
- 不暴露密钥的本地或远程鉴权方式。
- 退款、到期和服务不可用时的处理规则。

当前公开适配契约没有以上商业字段，因此仍按普通可选依赖处理。

## 可选商业路径

### 1. 市场付费 Skill

最轻量。PuKnowledge 继续开源，市场对“经过验证的工作流 Skill”收费。购买权益、
结账和分发由市场负责；PuKnowledge 不持有买家的支付资料。

适合：跨会话项目恢复、证据研究、长篇连续性等明确工作流。

### 2. 单独授权的本地扩展

特定扩展由独立产品授权，PuKnowledge 只读取本机可信权益并调用。需要定义稳定
的扩展协议，但不必建立云端多租户平台。

适合：Magpie/PuCatch 的高级采集、批量处理或专用模型能力。

### 3. 托管 PuKnowledge 服务

需要账户、租户隔离、远程存储、计量、账单、退款、备份、删除和安全运营。目前
不具备，不应为了上架 Skill 提前建设。

## 不应混用的表述

- “有许可证代码”不等于“用户现在可以付款购买”。
- “支付沙盒通过”不等于“生产商户和商品已获批”。
- “能调用 Magpie/PuCatch”不等于“该调用已计费”。
- “Agensi 可以销售 Skill”不等于“Agensi 托管 PuKnowledge MCP”。
- “开源软件免费”不妨碍单独销售工作流、支持或托管服务，但各自权益必须明确。

## 当前推荐

先保持 PuKnowledge MCP 免费开源，以一个永久免费 Starter Skill 验证真实安装和
跨会话恢复价值；高级 Skill Pack 是否收费，等外部用户数据和平台审核后决定。
不要在 PuKnowledge 中为本次 Agensi 验证新增账户、云计费或许可证系统。
