# 安装说明

完整安装步骤以仓库根目录 [README](../README.md) 为准。公开发行包含 `core`、`fs`、`longform`；不包含个人数据库、项目资料、远程 Tunnel 配置或维护者兼容入口。

对于已有项目目录，建议先生成一份单项目配置：

```bash
pu-knowledge-workbench \
  --config ~/.config/puknowledge/workspace.json \
  --init-workspace /absolute/path/to/your/project \
  --project-id my-project \
  --label "My Project" \
  --domain research \
  --enable-fs
```

该命令拒绝覆盖已有配置，不创建数据库，也不修改项目内容。生成后执行只读诊断：

初始化结果会明确返回 `workspace_interface=task`。它用于通用研究、产品和长期项目，不会根据目录名称猜测小说项目，也不自动创建 `longform` 结构。

```bash
pu-knowledge-workbench \
  --config ~/.config/puknowledge/workspace.json \
  --doctor
```

`READY` 只表示本机启动前提满足。`BLOCKED` 会列出失败检查；修复后重新运行即可。数据库尚未初始化显示为 `pending`，不是失败，因为数据库应由首次正式服务使用创建，而不是由诊断命令创建。

安装完成的最低标准：

1. `pu-knowledge-workbench --doctor` 返回 `READY`。
2. MCP 宿主能够调用 `workspace_guide`。
3. `workspace_list_projects` 只返回配置中显式登记的项目。
4. 未启用模块的工具不会出现在工具列表中。
5. `--doctor` 之后项目目录及数据库目录没有被诊断命令创建或修改。
